# 工程化规范

> 本文档用于指导 AI 和开发者生成稳定、一致、可维护的代码。强制红线以 `docs/开发强制约束.md` 为准。

## 项目基线

- 技术栈：Vue 3.5、TypeScript 5.3、Vite 5、Element Plus 2.5、Pinia、Vue Router 4、Vue I18n。
- 包管理器：pnpm 8+；Node 18+；路由模式：Hash。
- 样式体系：SCSS、CSS 变量、UnoCSS、Element Plus 变量。
- 请求层：统一走 `src/axios` 封装；Mock 目录为 `mock/`；路径别名 `@/` 指向 `src/`。

## 常用命令

```bash
pnpm dev
pnpm ts:check
pnpm lint:eslint
pnpm lint:format
pnpm lint:style
pnpm build:dev
pnpm build:test
pnpm build:pro
```

## 开发流程

1. 先阅读需求、相关代码、组件文档和既有实现，不凭文件名猜逻辑。
2. 优先复用项目已有组件、Hook、Store、工具函数、样式变量和类型。
3. 先补类型和 API，再做状态与交互，最后处理样式细节。
4. 小步改动，不重写无关模块，不覆盖用户已有改动。
5. 完成后按影响范围执行类型检查、Lint 或构建，并说明结果。

## 目录职责

```text
src/api/         # 接口请求与接口类型
src/assets/      # 图片、SVG 等静态资源
src/axios/       # 请求封装、拦截器、取消请求
src/components/  # 通用组件
src/constants/   # 全局常量
src/hooks/       # 组合式 Hook
src/layout/      # 布局框架
src/locales/     # 国际化语言包
src/plugins/     # 插件初始化
src/router/      # 路由配置
src/store/       # Pinia 模块
src/styles/      # 全局样式和变量
src/utils/       # 通用工具函数
```

## 命名规范

- Vue 页面和组件文件使用 `PascalCase.vue`；通用组件结构为 `src/components/Name/src/Name.vue` + `index.ts`。
- Hook 使用 `useXxx`；Store 使用 `useXxxStore`；API 方法使用 `get/create/update/delete + XxxApi`。
- 类型命名：请求参数 `XxxParams`，响应数据 `XxxRes`，列表项 `XxxItem`，表单模型 `XxxForm`。
- 常量使用全大写下划线或语义化枚举，避免散落魔法字符串。

## Vue 组件规范

- 优先使用 `<script setup lang="ts">`，组件显式 `defineOptions({ name })`。
- 页面入口保持清晰，复杂逻辑拆到局部组件或 Hook。
- props 和 emits 必须声明类型；父子通信优先 props/emits。
- 表单、表格、搜索、弹窗优先使用项目封装。
- 复杂插槽可用 TSX，但不要把普通模板整体改成 TSX。

## 页面组织

- 页面容器负责查询、列表、分页、弹窗/跳转、加载态、空态、删除确认、刷新。
- 局部组件负责独立表单、弹窗、抽屉、详情块，通过 props/emits 与页面容器通信。
- 一个菜单只对应一个业务文件夹，列表页、新建页、编辑页、详情页、当前列表专用弹窗都放在该菜单文件夹下。
- 路由可按业务语义配置为 `/asset/vehicle-list`、`/asset/vehicle-create`，但 `component` 必须指向同一个菜单文件夹下的页面。

推荐结构：

```text
src/views/pages/assetManagement/vehicleList/
  VehicleList.vue
  VehicleCreate.vue
  VehicleDetail.vue
  VehicleDialog.vue
  components/
  hooks/
```

## API 规范

- API 层只描述请求，不写页面提示、不操作 Store、不处理 DOM。
- 请求必须走 `src/axios`，不在业务代码中直接创建 axios 实例或直接 `fetch`。
- 参数和返回值必须有类型；分页字段、状态码、业务字段以接口约定为准。
- 删除、提交、更新等操作在页面层处理二次确认、loading 和成功提示。

## Store 规范

- 适合放入 Store：用户信息、Token、角色权限、路由菜单、TagsView、布局配置、主题、语言。
- 不适合放入 Store：单页查询条件、单次弹窗临时表单、可由接口重新获取的大体积列表、短生命周期 UI 状态。

## 路由规范

- `path` 清晰稳定；`name` 全局唯一；`component` 使用动态导入。
- `meta.title`、`meta.icon`、`meta.hidden`、`meta.noTagsView` 按菜单和标签页需求配置。
- 隐藏但允许跳转的页面必须配置 `hidden: true`、`canTo: true`，必要时配置 `followRoute` 和 `activeMenu`。
- 使用服务端动态路由时，mock 或后端路由也要同步新增隐藏页面，否则刷新可能 404。

## 表格规范

- 列表页优先使用 `Table + useTable`。
- 查询后回到第一页；刷新保持当前页；删除后处理页码回退。
- 金额、时间、枚举状态统一格式化；操作列固定右侧时注意窄屏可用性。
- 跨页选择必须配置 `row-key` 和 `reserveSelection`。
- 表格列配置建议拆到 `useXxxColumns.ts`，避免页面过长。

## 搜索规范

- 查询区优先使用 `Search + useSearch`。
- 搜索条件使用明确默认值；重置搜索同时重置分页到第一页。
- 远程下拉选项处理加载态和空数据。
- 搜索项过多时使用项目 Search 组件的展开/收起能力。
- 表格上方操作按钮优先放进 Search 的操作插槽，跟查询/重置保持同一区域。

## 表单规范

- 表单优先使用 `Form + useForm` 和 schema。
- 必填、长度、格式、联动规则写在 schema 或专用校验函数中。
- 字段名必须与接口字段或明确 DTO 字段一致；表单值必须定义类型。
- 提交前通过 `getElFormExpose().validate()` 统一校验，并做 loading 或 disabled 防重复提交。
- 编辑场景先重置再回填；关闭弹窗时清理校验和临时表单。
- 页面表单不要在业务页给 `.el-row` 单独添加 `row-gap`，间距由组件默认样式或表单项自身样式统一控制。
- 备注、说明、上传类字段默认占整行；附件上传统一使用 `FileUpload`。

## 弹窗规范

- 弹窗新增、编辑、详情应有明确模式，例如 `create`、`edit`、`detail`。
- 标题、按钮文案、禁用态随模式变化。
- 弹窗内部不直接假设父页面列表存在，提交成功后通过事件通知父页面刷新。
- 弹窗关闭时重置状态，避免上次数据残留。

## 详情与新建页模板

- 详情页分块优先使用 `DetailSection`，tab 切换优先使用 `DetailTabs`。
- `DetailSection` 的 `title-top`、`title-extra`、`header-extra` 插槽用于扩展 tab、按钮和标题补充内容。
- 新建/编辑页按业务分块使用 `DetailSection + Form`，底部按钮居中；提交或取消后关闭当前 TagsView 再返回列表。
- 列表页跳转的新建、编辑、详情页面不展示在菜单中，但必须保证路由可直接访问。

## 样式规范

- 中后台页面保持紧凑、清晰、易扫描；避免营销页式布局。
- 通用间距优先使用 UnoCSS 工具类或组件默认间距。
- 局部样式使用 `scoped`，全局样式放入 `src/styles/`。
- 避免深层选择器穿透；必须穿透 Element Plus 时使用 `:deep()` 并控制范围。
- 颜色、阴影、圆角优先复用 CSS 变量和 Element Plus 变量。
- 不写难维护的绝对定位布局，除非是图标、浮层或特殊视觉元素。

## 图标与资源规范

- 通用图标优先使用 `@element-plus/icons-vue`，业务和品牌图标使用本地 `svg-icon`。
- 本地 SVG 放在 `src/assets/svgs`；图片放在 `src/assets/imgs` 或业务模块资源目录。
- 不在业务代码中引用远程临时图片。

## 国际化规范

- 布局、菜单、路由、全局提示优先国际化。
- 新增语言键保持模块化命名，中文和英文语言包同步更新。
- 纯业务后台页面如当前模块未国际化，可保持模块一致，但不要混用多套风格。

## Mock 规范

- Mock 文件命名：`mock/模块名/index.mock.ts`。
- Mock 接口路径与真实接口保持一致或明确标注差异。
- Mock 数据覆盖列表、空数据、详情、创建、编辑、删除等关键场景。
- 随机数据可使用 `@faker-js/faker`，但字段结构必须稳定。

## 类型规范

- 业务类型就近放在 API 模块 `types.ts` 或页面模块下；全局通用类型放在 `types/`。
- 避免把所有类型堆进一个巨大文件。
- 接口响应、表单模型、表格行、枚举值分开命名。
- 对可能为空的字段显式使用 `null` 或 `undefined`。

## 错误与状态规范

- 页面至少考虑初次加载、空数据、请求失败、提交中、删除确认、删除中、权限不足或不可操作状态。
- 不要只实现理想路径。

## 提交规范

- Commit message 使用 Conventional Commits，允许类型见 `commitlint.config.js`。
- 常用类型：`feat`、`fix`、`docs`、`style`、`refactor`、`perf`、`test`、`build`、`ci`、`chore`、`revert`、`types`、`release`。

## 质量门禁

- 只改文档：无需构建，可检查 Markdown 格式。
- 改 TS 类型、API、Hook、Store：执行 `pnpm ts:check`。
- 改 Vue 页面或组件：执行 `pnpm ts:check` 和 `pnpm lint:eslint`。
- 改样式：执行 `pnpm lint:style`。
- 改路由、构建、全局组件、权限：建议执行 `pnpm build:dev`。

## 交付清单

- 是否新增或更新 API 类型。
- 是否复用项目封装组件。
- 是否处理加载、空态、错误、禁用、重复提交。
- 是否补充路由、菜单、权限、国际化。
- 是否遵循目录和命名规范。
- 是否执行必要质量检查。
- 是否没有改动无关文件。
